# 요청 35 · 모두 완료해줘

요청 원문은 실행 전에 USER_REQUESTS.md에 기록했다. 요청 34의 모의 주문 허용은 지속되며 실계좌 주문은 허용 범위가 아니다.

## 진행 중 변경

- 반복 관측한 모의 조회 HTTP 429에 대응하여 MOCK transport의 기본 최소 간격을 1.1초로 조정했다. 공식 상한을 바꿔 주장하는 것이 아니라 서버 공유 부하를 고려한 보수적 클라이언트 정책이다. LIVE는 기존 간격을 유지한다. 오류가 난 요청의 숨은 재시도나 토큰 재발급은 하지 않는다.
- `NhRequestPacer`는 기본 간격과 429 후 대기 중 큰 값을 적용하므로 감속 상태가 끝나도 모의 간격을 줄이지 않는다. 신규 단위 검사로 검증한다.
- WebSocket 구독 거절은 숫자 5자리 또는 WSS+숫자 5자리 응답 코드만 표시한다. 서버 자유문구·토큰·원문 메시지는 노출하지 않는다. 진단은 이 코드와 계좌 순번별 주문가능수량의 양수 여부를 기록한다.

## 전체 완료에 필요한 근거

COMPLETION.md와 RELEASE.md의 주문번호 대사·수정주가·뉴스 이용권·휴장일·실제 자동주문/파킹·장시간 기기 시험·Play 운영자/서명/심사 항목이 남아 있다. 코드로 추정하거나 체크 표시만 바꿔 완료 처리하지 않는다. 기존 계약/공식 답변 위치를 사용자에게 질의했으며 연결 진단과 로컬 검증은 독립적으로 계속한다.

## 실제 검증

실제 읽기 전용 진단에서 세 계좌의 잔고·체결·손익·가능수량·이력 내보내기가 모두 성공했다. 이번 실행에서 HTTP 429는 없었다(향후 불발생 보장은 아니다). 첫 계좌는 매수가능수량 양수, 다른 두 계좌는 0이었다. REST 가격/호가·상하한·정규장 조건은 통과했지만 신선도가 NO였다. WebSocket ACK는 WSS10015(공식 SDK의 앱키 동시 세션 초과)로 거절됐고 공유 연결도 시간 초과였다. DART 조회는 통과했다. 따라서 전체 FAIL이며 원인을 확인한 것이다.

다른 프로그램 세션을 강제 종료하지 않았다. 사용자가 직접 연결을 종료할 수 있는지 질의했다. 인증정보 및 임시 설치 제거를 확인했다.

주문 진단은 기존 보유가 있다는 이유만으로 주문가능 계좌를 제외하지 않도록 보완했다. 당일 주문 내역 없음은 계속 요구하고, 전후 종목별 보유수량 일치를 검사한다. 기존 주식을 매도하지 않는다. 신선한 시세를 최대 20회 읽기 전용으로 기다리며 신선도 기준을 완화하지 않는다. 주문·취소는 각각 최대 한 번이며 미확정 결과 보존 규칙을 유지한다.

첫 주문 진단에서 후보 1의 주문가능/계좌 격리/시세 사전 검사까지 통과했지만, `mock_order_probe` 이름이 SecureVault의 영문 소문자 계약에 맞지 않아 PREPARED 저장 시 거절됐다. 주문은 전송되지 않았고 임시 키/설치는 정리됐다. 이름을 `mockorderprobe` 상수로 수정하고 기본 계측 시험에 실제 원장 저장/새 vault 복원 검사를 추가했다. 첫 시도의 전송 전 종료를 확인하고 증거를 보존한 후 수정본 검증을 진행한다.

## 실제 주문과 읽기 전용 복구 결과

수정 후 모의 005930 지정가 1주 매수 요청 1회와 반환된 시장주문번호에 대한 취소 요청 1회가 모두 접수됐다. 후속 조회가 한 행이어야 한다는 진단 조건 때문에 처음에는 FAIL로 종료하고 암호화 원장/임시 설치를 보존했다. 주문이나 취소를 재전송하지 않았다.

읽기 전용 복구에서 원주문/취소로 보이는 두 행을 확인했다. 두 행 모두 종목 일치·주문수량 1·체결수량 0·미체결수량 0이고 취소수량은 각각 0과 1이었다. 당일 주문이 없었던 계좌에 대한 완결된 전체 페이지 조회이므로 계좌 범위의 전량 미체결 취소 종료 증거로 사용했다. 시장번호/통합번호 또는 그룹 소유권의 대응 근거로 사용하지 않았다.

`accountTerminal`은 1~2행, 종목/정수 수량 일치, 체결/잔여 0, 취소 합계 1을 요구한다. 빈 내역·미체결·체결·다른 종목·중복 취소·분수 수량·3행 이상은 거절한다. 이 판정의 기기 검사 2개를 통과한 뒤 다시 읽기 전용으로 종료 상태와 새 잔고 조회를 확인했다. **모의 주문 1회/취소 1회, 체결 0, 종료 확인 후 키와 임시 설치 제거 완료.** 원 진단 실패는 복구 성공과 구분해서 보존한다.

복구 전 버전은 보유수량 기준값을 영속화하지 않아 재시작 후 보유수량 전후 비교를 입증하지 못했다. `recovery_holdings_comparison=NOT_PROVEN`으로 기록하며 최신 진단은 원장에 기준값도 암호화 저장한다. 수정된 전체 주문 진단을 다시 주문하여 통과로 만들지는 않았다. 실제 체결/매도/IOC/전략·그룹·파킹 E2E 통과를 의미하지 않는다.

## 남은 차단 조건

1. 같은 앱키의 외부 WebSocket 세션 해제 후 연결 재검증 필요. 서버 WSS10015를 확인했고 다른 앱 세션을 강제로 종료하지 않았다.
2. 공식 주문번호 대응/확정 비용, 수정주가 산식, 뉴스 이용권, 휴장일 공급 근거가 필요하다. 공개 명세 재조회만으로 입증되지 않았다.
3. 위 근거에 따른 실제 그룹/전략/파킹 자동주문 및 장시간 기기 검증과 Play 운영자·정책·서명/심사 게이트는 남아 있다. 따라서 요청 전체 완료 및 정식 릴리즈로 보고하지 않는다.
