# 적응형 타겟가격 추적 — 요구사항 및 미구현 경계

2026-09-19 사용자 요구를 기록합니다. 이 문서의 추적 기능은 **아직 구현하지 않았습니다**. NamuMagic 저장소 URL과 기준 코드 확인을 요청했으며, 타겟 갱신 규칙을 임의로 정하지 않습니다.

## 용어와 계층

- 전략 제시 가격: 상위 전략이 매수/매도를 제안하는 기준 가격.
- 추적 타겟가격: 실제 거래가격 흐름에 따라 추적 계층이 관리하는 주문 트리거 가격. 전략 제시 가격과 별도 상태로 보존해야 합니다.
- 주문 실행 가격: 트리거 성립 후 공통 위험 검사·사전 저널을 통과해 실행 계층에 보내는 가격. 타겟 도달만으로 주문·체결을 확정하지 않습니다.

응용/전략 → 타겟 추적/주문 판단 → Broker 실행 계층을 유지합니다. REST 가격 제공자는 주문 Broker 및 리서치 이력 제공자와 분리된 포트로 교체할 수 있어야 합니다.

## 요청된 조회 방식

타겟과 현재가의 차이가 멀면 비주기 REST 조회, 가까우면 WebSocket으로 상세 추적합니다. 차이율은 `abs(현재가 - 타겟) / 타겟`으로 산정할 계획입니다. 사용자 문구의 10% 이상/이내는 경계가 겹치므로 **정확히 10%는 상세 추적**으로 처리할 예정입니다. 실제 타겟 갱신 알고리즘은 NamuMagic 확인 후 확정합니다.

동일 종목이 여러 그룹에 있으면 타겟 상태는 그룹·매매 방향별로 분리하고, 한 타겟이라도 근접하면 해당 종목의 단일 공유 구독을 유지해야 합니다. 구독 해제는 모든 소유자가 원거리/추적 종료일 때만 가능합니다. 구독 한도를 넘으면 추적 누락을 숨기지 말고 주문을 차단해야 합니다.

비주기 REST의 의미는 사용자에게 확인 중입니다. 응답이 없으면 거리·변동성에 따른 가변 간격 조회를 기본안으로 사용하되 공식 호출 한도·429 백오프·오래된 가격 거절을 적용합니다. REST에서 근접을 확인한 직후에는 새 WebSocket 가격이 유효해질 때까지 주문하지 않아야 합니다. 실제 REST 시세 필드·서버 시각·시장 상태 명세 확인 전 임의 엔드포인트를 만들지 않습니다.

## 현재 상태

현재 코드는 기존 고정 WebSocket 구독과 15초 그룹 평가를 그대로 사용합니다. 신규 추적 기능이 반영된 것으로 해석하면 안 됩니다. NH 그룹 체결 대사와 필수 데이터 게이트도 유지됩니다.
