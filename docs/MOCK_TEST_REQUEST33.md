# 요청 33·34 모의계좌 검증 (2026-10-02)

사용자 원문은 [USER_REQUESTS.md](USER_REQUESTS.md)에 실행 전에 기록했다. 요청 34는 모의계좌 주문을 명시적으로 허용한다. 실계좌 주문이나 출시 잠금 해제 허용으로 해석하지 않는다.

## 발견 및 수정

[NHPlug 공식 명세](https://www.nhplug.com/openapi-docs/krstock/openapi.json)를 다시 확인했다. 받은 파일 SHA-256은 `694fc0e709b46c6f8466b98450a2f0564371ba02bd71ec771d223ef2c47b2448`이다. 당일 주문체결 조회의 현재 응답은 `Output_0` 배열인데 기존 앱은 `Output_1`만 읽었다. 그 결과 존재하는 내역을 빈 목록으로 표시할 수 있었다.

`NhBroker.executions → NhExecutionParser.parse → rows`에서 현재 배열과 이전 배열 봉투를 명시적으로 구분한다. 두 배열의 동시 존재·잘못된 타입·분수 수량·수량 관계 오류를 거절한다. 체결 평균은 누적 `cns_amt / tot_cns_qty`로 계산하며 임의로 가격에 1,000을 곱하지 않는다. 현재 형식의 체결 금액이 없으면 추정하지 않고 실패한다. 미체결 평균은 0이다. 이 변경은 체결 조회용이며 시장주문번호와 통합주문번호의 대응 관계 또는 그룹 소유량을 추정하지 않는다.

## 주문 진단 범위와 흐름

`MockOrderProbeTest.isolatedLimitAndCancel`은 androidTest 전용이며 기본 실행에서는 제외된다. 요청 날짜와 명시적 opt-in 인수가 필요하다. Debug 전용 빈 설치에서 RSA/AES-GCM 봉투로 인증정보를 받아 Keystore 기반 vault에 저장한다. 주문·취소 주소가 `moapi.nhplug.com:8443`이고 계좌 환경이 MOCK인지 검사한다.

진단 흐름은 인증 → 잔고/당일 내역이 없는 모의계좌 선택 → 신선한 현재가/하한가/주문가능수량 확인 → 암호화 PREPARED 원장 → 시세 재확인 → SUBMITTING 원장 → 005930 하한가 지정가 1주 주문 1회 → 접수번호 저장 → CANCEL_SUBMITTING 원장 → 반환된 시장주문번호로 전량 취소 1회 → 읽기 전용 조회 최대 5회 → 계좌의 단일 주문 수량 1·체결 0·잔여 0·취소 1 및 보유 없음 확인이다. 가격은 100만원 이하이고 매수호가보다 10% 이상 낮아야 한다. 접수는 체결로 표시하지 않는다.

이는 사용자가 허용한 고정 수량 프로토콜 진단이다. 추천·전략·파킹 엔진을 실행하지 않으며 운영 앱의 공통 연구/위험 게이트와 자동매매 잠금은 변경하지 않는다. 생산 주문의 IOC 처리, 매도/실제 체결, 전략별 소유권 대사는 이 진단의 통과 항목이 아니다.

SUBMITTING 이후 불명확한 결과는 자동 재시도하지 않는다. 취소 접수만으로 종료를 확정하지 않는다. 계좌 종료 증거가 없으면 암호화 원장·키·임시 설치를 보존한다. 호스트 실행기는 중복 시도를 막는 파일을 배타 생성하며, `local_cleanup=PASS`가 확인된 경우에만 새 임시 설치를 제거한다. 원문 응답, 키, 계좌번호는 출력·커밋하지 않는다. 기존 사용자 설치는 변경하지 않는다.

## 실제 검증 상태

- JVM 1,163개 통과(신규 파서 4개 포함). lint 오류 0, 버전 관련 경고 13개. Debug APK·Release AAB·AndroidTest APK 빌드 성공.
- 장중 실제 읽기 전용 진단: 인증 및 모의계좌 3개 발견, 계좌 1/3 잔고, 세 계좌 체결/손익/가능수량 조회·이력 내보내기, 현재 REST 시세 신선도·호가·상하한·정규장 검사, 가격 이력, DART 기업코드/공시/재무 통과. 계좌 2 잔고 HTTP 429, WebSocket 수신/공유 lease 시간 초과 때문에 전체 FAIL. 가격 이력 응답 성공은 수정주가 증명이 아니다.
- 주문 진단 1: 빈 계좌 선택 이후 사전 검사 IllegalArgumentException, `buy_dispatch` 이전 중단. 당시 상세 위치 미수집.
- 주문 진단 2: 정적 소스 위치만 출력하도록 보강한 뒤 검사. 시세 통과, 선택 계좌 주문가능수량이 1 미만이어서 전송 전 중단(당시 MockOrderProbeTest:134). 다른 계좌의 주문가능 여부를 이 결과로 단정하지 않는다.
- 주문 진단 3: 첫 빈 계좌만 고르지 않고 가능수량까지 검사하여 후보를 선택하도록 개선했다. 이번에는 계좌 선택 전 `NhCurrentPriceProvider:46`의 가격/호가/신선도 조건이 거절되어 전송 전 중단. 세 하위 조건 중 어느 것이 거절됐는지는 수집하지 않았다.
- 앞선 진단의 `retain_install=NO`, `local_cleanup=PASS`, `buy_dispatch` 없음으로 전송 전 종료를 확인한 뒤에만 새 진단을 시작했다. 각 시도의 원래 중복 방지 파일과 결과를 보존했다. 불명확한 주문의 재전송은 없었다.
- **실제 주문 전송 0건, 취소 전송 0건. 접수/체결/취소 성공으로 보고하지 않는다.** 세 진단 모두 키 제거와 임시 설치 제거 완료. Android 전체 회귀 시험은 XML 39개 중 37개 통과·실제 API opt-in 2개 제외, 실패/오류 0이다. 기존 preview 설치·폰트 배율·adb 권한 보존과 임시 설치 제거를 확인했다.
- 자동전략의 실제 주문 E2E 및 출시 게이트는 아직 완료되지 않았다.
