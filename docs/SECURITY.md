# 보안 설계

## 요청 29 · 공유 채널과 기업 ZIP 처리

연구 요청 설정은 기존 계좌별 settings.enc에 보관한다. 실행 중 갱신 작업은 세션 취소에 종속되며 늦은 조회는 취소/세대 검사를 통과해야 반영된다. 전체 묶음 실패 시 이전 근거를 계속 매수 승인으로 쓰지 않는다. 기업 목록 캐시는 인증키를 보관하지 않고 필요한 다운로드 시점에만 vault 접근 함수를 호출한다.

공유 시세에는 계좌 인증/잔고/체결 데이터를 넣지 않는다. 각 lease가 요청한 종목과 ACK가 모두 맞을 때만 시세를 분배한다. 다른 계좌 정지/재연결 콜백이 이미 닫힌 lease에 전달되지 않도록 세대와 현재 등록을 확인한다.

기업 고유번호 ZIP은 공식 OpenDART HTTPS에서만 수신하며 디스크에 풀지 않는다. 압축 입력 10MiB/해제 XML 64MiB, 단일 CORPCODE.xml 항목, 필드 4KiB/상장 매핑 50,000개 상한을 적용한다. DTD/외부 엔티티를 거절하고 중복 종목코드·잘못된 식별자는 실패로 처리한다. 값/키/인증 URL은 로그로 출력하지 않는다.

## 요청 28 · 조회 경계와 진단 판정

HTTP 429는 원래 호출의 실패를 유지하고 공유 transport의 후속 호출만 감속한다. 요청을 자동 재전송하거나 토큰을 재발급하지 않는다. 호출 간격은 단조 시계 기준이며 대기 후 주문 dispatchGuard/취소 검사를 유지한다. 인증·응답 본문·Retry-After 원문을 로그에 추가하지 않는다.

NhBroker의 잔고·가능수량·당일 체결·손익 조회는 계좌의 증권사와 거래 환경을 네트워크 호출 전에 확인한다. 상위 controller 검사만 신뢰하지 않는다. 실제 키 진단은 모든 반환 모의계좌를 순회하지만 출력에는 순번과 개수만 남긴다. 실제 이력의 CSV/ZIP은 메모리에서만 생성하며 외부 파일을 남기지 않는다. 시험용 계좌 이력도 root vault 전체 정리 대상이다. 단계 실패를 숨기지 않도록 정리 후 `overall=FAIL`과 실패 JUnit을 반환한다. 상세 범위는 [모의 검증](MOCK_VERIFICATION.md).

## 실제 키 조회 시험

일봉 window 예외는 period 경로·일봉 구분·명시한 개수(1~250)가 일치하고 실제 수신 개수가 충족될 때만 허용합니다. 주문·잔고·체결의 불완전 페이지를 성공으로 취급하지 않습니다.

`CredentialProbeTest`는 androidTest 전용이며 `credentialProbe=1`로 명시한 disposable Debug 설치에서만 실행합니다. 기존 암호화 데이터가 있으면 중단합니다. 기기에서 생성한 일회성 RSA 공개키로 AES-GCM 전달 키를 감싸고 ADB stdin으로 암호문만 전달합니다. 개인키/복호화 자격증명은 메모리에서 사용하며 기기 저장은 SecureVault만 사용합니다. 예외 메시지·URL·응답 본문·계좌/금액/토큰을 출력하지 않고 단계 상태와 엄격히 추출한 HTTP 코드만 기록합니다.

주문/취소/서비스 시작을 호출하지 않습니다. 종료 시 시험이 생성한 credentials/token과 파일/Keystore 키를 제거하고 새로 설치한 disposable 앱을 제거합니다. 서버 토큰 폐기를 의미하지 않습니다. 원본 설정은 변경하지 않습니다. 호스트 복호화/전달 도구와 개인 경로는 커밋하지 않습니다. JVM/Python 문자열의 메모리 완전 삭제는 보장하지 않습니다.

NH 인증은 정확한 `application/x-www-form-urlencoded`와 빈 바이트 본문을 사용합니다. 문자열 본문에서 자동 추가된 charset 때문에 실제 인증이 403으로 거절되는 문제를 수정했습니다. 인증 URL은 공식 발급자 HTTPS로만 전송하고 출력하지 않습니다.

## 테스트 APK 서명과 격리

`previewRelease=true`는 release 빌드에 `.preview` ID와 Preview 앱 이름을 적용합니다. Debug는 `.debug` ID와 Debug 이름을 사용합니다. API 키/Keystore/데이터는 UID별로 격리됩니다. Preview도 실거래 잠금을 유지합니다.

`scripts/package_test_apks.py`는 저장소 밖의 테스트 keystore만 받고 비밀번호는 환경 변수 이름을 통해 서명 도구에 전달합니다. production ID 또는 예상과 다른 debuggable APK는 거절하며 서명 검증·SHA-256을 남깁니다. 테스트 서명은 Play 정식 서명을 대체하지 않습니다. 업데이트의 서명 연속성은 [Android 공식 문서](https://developer.android.com/studio/publish/app-signing)를 따릅니다.

## 보호 대상 및 위협

인증키/secret/토큰, 계좌번호, 주문 내역과 로그가 대상입니다. 악성 오버레이, 화면 캡처, 외부 앱의 intent 호출, 백업/기기 이전 유출, HTTP 로그 노출, 중간자 공격, 중복 주문과 암호문 손상을 방어합니다. 루팅된 OS·악성 키보드·기기 인증을 통과한 공격자·물리적 완전 탈취에 대한 절대 보호는 보장하지 않습니다.

## 구현

- Android Keystore AES/GCM/NoPadding. 키는 Keystore에서 생성하며 추출하지 않습니다. 매 암호화에 새 IV, 파일명 AAD, 인증 태그 적용. 기기별 하드웨어 지원을 따르며 StrongBox 사용을 강제하거나 보장하지 않습니다.
- `noBackupFilesDir` 안에 AtomicFile로 쓰기 완료 후 교체. credentials, token, settings, journal, events, snapshot 암호화. 백업과 Android 12+ 기기 이전 명시 차단.
- 키의 인증 바인딩은 매 호출마다 요구하지 않습니다. 사용자가 승인한 백그라운드 세션이 필요하기 때문입니다. 앱 화면 진입은 기기 PIN/패턴/비밀번호 확인을 강제하고 재진입 시 다시 잠급니다.
- 키 입력은 비밀번호 변환, 자동 교정 비활성, 화면 상태 복원 저장을 사용하지 않음. 저장 후 입력창 비움. JVM의 불변 문자열과 입력기 메모리 완전 삭제는 보장하지 않습니다.
- `FLAG_SECURE`: 스크린샷·일반 화면 녹화·최근 앱 미리보기 보호. Android 12+ `HIDE_OVERLAY_WINDOWS`와 가려진/부분 가려진 터치 거절 적용.
- 외부 노출 컴포넌트는 실행용 MainActivity 하나. 주문 intent, exported service/receiver/provider, WebView, JavaScript bridge, accessibility 서비스, 임의 호스트 설정 없음.
- 인터넷, 알림, foreground service/specialUse, 오버레이 숨김 이외 위험 권한 없음. 연락처·SMS·위치·저장소·다른 앱 목록 권한 없음.
- 공식 HTTPS/WSS만 사용. 플랫폼 인증서/호스트 검증 유지. `trust-all`, 사용자 CA 우회, 인증서 오류 무시 없음. 리다이렉트 비활성. 서버 인증서 중간 체인 오류도 실패로 처리.
- 키는 발급자의 공식 인증 요청에만 포함합니다. “폰 내부에만 저장”은 서버 인증 전송까지 금지한다는 의미가 아니며 앱 내에서 이를 고지합니다.
- 원시 HTTP 본문·URL·토큰·키·계좌번호를 logcat이나 사용자 로그에 기록하지 않음. 로깅 interceptor와 원격 crash/analytics SDK 없음.
- 암호문 손상 시 빈 저장소로 시작하지 않고 거래를 잠급니다. 삭제는 명시적인 확인 후 전체 키와 데이터를 제거합니다. 기기 삭제는 브로커 토큰/주문 취소가 아니므로 공식 포털에서 별도 폐기할 수 있습니다.

## 주문 안전성

2026-09-19 재검증에서 전송 후 저널 쓰기 실패 시에도 정지 플래그가 먼저 내려가도록 보강했습니다. UNKNOWN 저장이 실패하면 기존 SUBMITTING이 재실행 후에도 미확인 주문으로 남습니다. 정상 복호화된 JSON이라도 필수 배열이 없거나 타입이 다르면 저장소 초기화를 실패시킵니다. 손상된 구조를 빈 주문 기록으로 처리하지 않습니다.

시세 15초·잔고 60초 한도는 정수 초 절삭 없이 비교합니다. 실행 중 세션 재시작으로 손실 기준을 바꿀 수 없으며 다른 종목/비정규장 가격으로 청산 신호를 만들지 않습니다. 자동매매 중 수동 조회/설정 작업을 차단해 반복 작업과 화면 액션의 상태 변경 경쟁을 줄입니다.

사전 영속 저널, 직렬 주문, 하루 종목/방향 중복 방지, 계좌/모의 구분, 오래된 시세·잔고 차단, 현금 가능수량, 한도, 지정가 IOC, 미확인 주문 이후 전체 거래 차단. 정지 플래그는 호출 직전 확인하나 네트워크로 이미 전송된 주문을 되돌리지는 못합니다. 공휴일 달력 자체는 미구현이며 서울 평일 시간과 신선한 실시간 정규장 거래소 메시지를 함께 요구합니다.

## 교체 가능한 계층의 보안 경계

TradingController/UI에서 SecureVault와 HTTP 구현 접근을 제거했습니다. ApplicationStorage는 키 쓰기와 존재 확인만 제공하고 키 읽기는 제공하지 않습니다. AppContainer와 발급자 어댑터가 필요한 인증정보를 내부에서 사용합니다. 전략에는 네트워크/저널 객체를 전달하지 않고 공통 안전 엔진을 유지합니다. 브로커 교체 시 기록은 brokerId/계좌/환경으로 구분하며 기존 필드 미포함 NHPlug 기록은 nhplug 이름공간으로 읽습니다. 이 변경은 실거래 잠금을 해제하지 않습니다.

## 그룹 소유권과 정기매수

전략/그룹 설정(groupbook), 누적 체결(groupfills)을 기존 Keystore/AtomicFile로 암호화하며 전체 삭제 대상에 포함합니다. 주문 저널에는 strategyId/groupId/occurrence를 추가하고 기존 기록은 빈 그룹으로 보존합니다. 같은 종목의 다른 그룹 수량을 합쳐 매도하지 않습니다. 부분/미확인/미종료 그룹 주문이 있으면 다음 그룹 주문을 보류합니다. 누적 체결 후퇴·다른 주문·그룹 초과 매도·계좌 잔고 불일치·최종 체결 정정은 실패로 처리합니다. 그룹 설정만 켜거나 일정 도래만으로 주문하지 않으며 사용자가 시작한 세션과 기존 데이터/출시 게이트를 모두 요구합니다.

## 지속 실행 세션
사용자가 시작한 서비스의 시간 만료와 최근 앱 목록 제거 시 정지를 없앴습니다. 화면은 계속 재인증을 요구하며 서비스는 정지 알림을 유지합니다. START_NOT_STICKY와 재부팅 미등록으로 프로세스 종료 후 무인 주문 재시작은 하지 않습니다. 시스템 제한 onTimeout에서는 즉시 정지합니다. Doze 우회 권한·알람·백엔드 키 전송은 추가하지 않았습니다.

## 파킹 설정·소유권
파킹 설정은 기존 `groupbook` 암호화 파일에 저장하고 체결은 `groupfills`, 주문은 사전 영속 저널을 사용합니다. 새 서버/키 전송/권한은 없습니다. 예약 전략·그룹 ID는 사용자 그룹이 사용할 수 없고, 거래 기록이 생긴 파킹종목의 변경을 금지합니다. 외부 수동 보유분을 매도하지 않으며 미완료 주문이 있으면 파킹/전략 모두 대기합니다. 파킹 매수도 필수 리서치 게이트를 적용합니다.

## 2026-09-20 추적 통신 변경
운영 호스트 허용은 공식 currentPrice/period 읽기와 시세 WS에 한정합니다. 주문 호스트·실거래 빌드 잠금은 유지합니다. 시세 연결 장애는 ACK 확인된 WS 또는 신선한 REST로만 복구하며 주문 API는 재시도하지 않습니다. 원본 NamuMagic의 비공개 코드/설정/키는 저장소와 CI에 포함하지 않습니다. 추적 극값은 아래 추가 정책에 따라 계좌별 암호화 저장하며 정지·계좌 전환 시 메모리만 비웁니다.

## 전송 시점과 수동 조회 검토
가능수량 응답 대기/저널 쓰기 사이에 장 마감 또는 잔고 만료가 발생하면 전송 직전 다시 차단합니다. 예약 이후 불확실 상태의 자동 재시도 금지는 유지합니다. 수동 시세는 연결된 설정/보유 종목만 정지 상태에서 조회하고 사용자 입력 URL/임의 종목을 API로 전달하지 않습니다.

전송 만료는 OrderIntent.expiresAt으로 전달·암호화 저장합니다. NhBroker가 토큰/호출 간격 대기 후 HTTP 직전에도 검사합니다. 기존 정수 초 절삭(5.999초 허용)을 제거했습니다. Broker 호출 전 확실한 미전송은 REJECTED로 기록하고 정지합니다. Broker 호출 후 예외는 UNKNOWN이며 재시도하지 않습니다. REJECTED 저장 실패는 SUBMITTING을 남기고 정지하므로 후속 주문을 막습니다.
# 2026-09-20 추적 이력 및 시세 옵션

`tracking.enc`에 매매 타겟·전략/그룹/회차·최고/최저·활성 상태를 기존 Keystore AES-GCM/파일명 AAD/AtomicFile 방식으로 저장한다. 앱 전용 noBackup 디렉터리를 사용하며 원시 API 응답·키·secret·ready 상태·시세 캐시는 저장하지 않는다. 증권사·계좌·거래 환경을 모두 일치시켜 복원한다. 전체 데이터 삭제 대상에도 포함한다. 비활성 이력은 자동으로 삭제하지 않는다.

설정의 WebSocket ON/OFF도 기존 암호화 설정에 저장한다. OFF에서도 시세 신선도·가격제한·원장/위험 검사는 동일하다. 복원된 최고/최저는 주문 승인이 아니며 새 당일 시세 및 최신 전략·연구 근거가 필요하다.

`TrackingStorageException`은 REST 재시도 오류로 흡수하지 않는다. REST 루프와 WebSocket 콜백 모두 이 예외를 자동매매 정지·저장소 오류 잠금으로 전달한다. 저장하지 못한 극값으로 주문을 계속하지 않는다.
# 2026-09-20 비동기 및 설정 화면 보완

이전 세션 콜백과 정지 후 늦은 조회 결과를 세대 검사로 폐기한다. 전체 데이터 삭제는 진행 중 작업 종료 전 차단한다. 키 입력은 여전히 rememberSaveable을 사용하지 않고 저장 요청 후 비운다. 설정을 계좌/시세/보안 전체 화면으로 분리하되 기기 인증·FLAG_SECURE·Keystore·백업 차단을 변경하지 않는다. 테스트 화면의 합성 계좌는 androidTest에만 존재한다.


## 요청 25 계좌 격리

계좌번호를 파일명으로 노출하지 않고 증권사/환경/계좌 식별 조합의 SHA-256 namespace를 사용한다. GCM AAD도 계좌 namespace를 포함하여 암호문 교환을 거절한다. 각 계좌의 주문 저널·설정·통계는 별도 파일이며 root 공유 인증과 구분한다. UI 선택 상태 복원 키는 계좌번호 대신 목록 인덱스다. 모든 계좌가 정지/요청 종료 상태일 때만 공유 키 교체·전체 삭제를 허용한다. 키 교체 시 모든 enable 해제·연결 폐기, 기록 보존. 자동운용 enable을 저장해도 프로세스 복원만으로 주문을 시작하지 않는다. 전체 삭제는 앱 내부의 검증된 namespace/고정 파일명만 대상으로 한다.

## 사용자가 내보내는 개인 통계 (요청 26)

`CreateHistoryDocument`는 `CATEGORY_OPENABLE`을 명시해 스트림 출력 대상 문서를 요청한다. 반환 URI도 content 스킴인지 확인하고 다른 경로는 거절한다.

CSV/ZIP은 사용자가 시스템 파일 선택기로 고른 단일 문서에 기록한다. 넓은 저장 권한/영구 URI 권한/임시 평문 파일/네트워크 업로더는 추가하지 않는다. 키/토큰/전체 계좌번호/주문번호는 제외한다. CSV 수식 입력 방지와 필드 인용, ZIP 고정 항목명을 적용한다. 내보낸 복사본은 **암호화되지 않으며**, 사용자 선택 클라우드 제공자의 동기화/앱 삭제 이후 잔존이 가능함을 저장 전에 UI에 표시한다. 내부 Keystore 보호와 별개다. 오류 메시지는 경로·URI·문서 제공자 예외를 노출하지 않는다. 프로세스 사망 시 현재 계좌로 내보내기를 대체하지 않는다. 공유 저장 오류는 UI와 서비스 시작 경계 모두에서 차단한다.
