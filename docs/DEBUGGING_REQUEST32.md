# 요청 32 · NHPlug / UI / 설정 점검

2026-10-01. 사용자 원문은 실행 전에 USER_REQUESTS.md 요청 32에 기록했다.

## 수정 경계와 흐름

- `SettingsDialog → MultiAccountController.saveCredentials → discovery AccountRuntime`: 공유 키 저장의 완료 메시지와 오류 여부를 선택 계좌의 이전 메시지와 분리한다. `savingCredentials`는 완료까지 전체 작업 잠금을 유지한다. 취소도 선택 계좌가 아니라 공유 작업 소유자에게 전달한다.
- `discoverAccounts`: 공유 저장소 오류 시 호출 전에 거절한다. 기존에는 하위 runtime이 작업을 거절해도 상위의 discovering 상태가 남을 수 있었다.
- 설정의 데이터 삭제: 저장소 오류가 있어도 전체 계좌가 idle이면 복구용 삭제 확인을 열 수 있다. 확인창이 열린 후 다른 작업이 시작되면 확인 버튼도 잠긴다. 삭제 결과/실패를 확인하도록 설정 화면을 유지한다. 실제 사용자 데이터 삭제 시험은 하지 않는다.
- 파킹 설정: 저장소 오류 시 편집/저장을 차단하고, 선택 계좌 변경 시 이전 계좌의 초안과 저장 대기 상태를 폐기한다. 전체 화면 편집기에 시스템/키보드 inset을 적용한다.
- 계좌 목록 갱신 버튼도 공유 저장소 오류를 반영한다.
- 키보드가 열린 전체 화면 다이얼로그의 실제 창 크기와 Compose 스크롤 경계가 달라 하단 입력란이 가려지는 문제를 추가 재현했다. `SettingsDialog`/`ParkingEditor`의 `decorFitsSystemWindows=false`와 `safeDrawingPadding/imePadding`으로 크기 처리 소유자를 통일하고 파킹 스크롤 영역에 남은 높이를 명시적으로 배분했다. 제목/버튼 중앙 정렬과 입력 너비도 통일했다. 입력 값 변경뿐 아니라 키보드가 열린 하단 입력란의 실제 가시성을 검사한다.

신규 MultiAccount JVM 3개는 수정 전에 모두 실패했다. 합성 runtime으로 키 저장 성공/실패, 공유 작업 취소 대상, 저장소 오류 후 무한 busy를 재현한다. Android 테스트는 가짜 삭제 콜백으로 확인창의 상태 변화와 결과 표시, 파킹 편집의 저장 잠금/계좌 변경을 검증한다.

## 실제 NHPlug 읽기 전용 진단

수정 전 기준 APK로 별도의 임시 debug 설치에서 1회 실행했다. 사용자 승인된 암호화 INI의 키를 메모리에서 복호화하고, 기기가 만든 공개키로 봉인해 전달했다. 원문 키/계좌 번호/잔고/응답 본문은 보고서나 캡처에 넣지 않았다. 종료 후 키·시험 데이터·임시 APK 제거 성공. 주문 API는 호출하지 않았다.

| 항목 | 실제 결과 |
|---|---|
| 암호화 저장 / NH 인증 | PASS |
| 모의 계좌 목록 | 3개 |
| 계좌 1·2 잔고 | PASS |
| 계좌 3 첫 잔고 조회 | FAIL HTTP 429 |
| 각 3계좌 체결내역·손익·매수/매도 가능수량 조회 | PASS |

| 현재가 응답 구조/호가 양수·정렬/상하한 범위 | PASS |
| 현재가 신선도 검증 | FAIL (fresh=NO, 오래된 시세 거절) |
| 일별 가격 이력 | PASS (원시 일봉이며 수정주가 승인 아님) |

| WS 최초/변경 틱·재연결 단계·공유 3 lease | 시간 초과 |
| OpenDART 기업코드·공시·재무 | PASS |
| 전체 판정 | **FAIL** |

종료 후 시계 대조: 기기 2026-10-01 14:49:34 UTC, 시간 도구 14:49:35 UTC(한국 23:49). 장외 진단이므로 최신 시세와 WS 틱은 장중 재검증해야 한다. 서버의 regular_session=YES만으로 운영시간을 보장하지 않는다. 틱 대기와 ACK를 합친 재연결 단계의 시간 초과를 ACK 실패라고 단정하지 않는다. 계좌 3의 후속 이력 단계가 성공했어도 앞선 429 실패를 소거하지 않는다.

NHRequestPacer는 기존대로 최초 요청 실패를 호출자에게 전달하고 후속 요청만 감속한다. 거래 재시도나 신선도 기준 완화로 성공을 만들지 않는다. 공식 API 목록은 [NHPlug API 서비스](https://www.nhplug.com/apiservice)에서 확인했으며, 공개 목록 열람은 실제 기능 통과나 데이터 재배포 권한의 증거가 아니다.

## 검증 상태

최종 빌드·전체 회귀·기기 UI 결과는 VERIFICATION.md에 기록한다. 이번 작업은 실주문/장시간 운용/모든 외부 제공자 계약의 완료를 뜻하지 않는다. GroupExecutionSource 주문번호 대사, 수정주가 계약, 허가된 뉴스 등 기존 출시 잠금은 유지한다.
